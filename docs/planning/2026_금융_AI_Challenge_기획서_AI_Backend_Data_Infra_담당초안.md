## 2. 아이디어 기획 핵심내용(요약) — 기술 관점 보완안

- 예비창업자·소상공인·프리랜서의 **유형·지역·업종·자본금 등 프로필**과 정부지원금·정책자금 대출·지자체 혜택 데이터를 연결해, 사용자별로 확인할 필요가 있는 지원사업을 좁혀주는 AI 기반 금융 의사결정 지원 서비스를 구현한다.

- 사용자가 입력하거나 업로드한 **매출장표(CSV/엑셀)·소득·현금흐름 데이터**를 분석해 재무 상황을 정량적으로 진단하고, 신용점수만으로 설명하기 어려운 상환 여력과 재무 상태를 이해하기 쉬운 근거로 변환한다.

- 창업 초기 비용·매출·지출·대출 조건을 바탕으로 **버틸 수 있는 기간과 사업 악화·폐업 시 잔존 채무를 계산**하고, 계산 결과와 사용자 조건을 지원사업 탐색 결과와 연결한다.

- AI는 단순히 금융정보를 생성하는 역할이 아니라, 사용자의 자연어 질문을 이해하고 필요한 조건과 데이터를 찾아 **검증된 검색·계산 결과를 사용자 상황에 맞게 설명하는 역할**을 수행하도록 설계한다. `[TEAM DECISION]`

## 4. 서비스 컨셉 및 차별성 — AI·Backend 관점 보완안

- **구조화된 맞춤 매칭:** 예비창업자 / 소상공인 / 프리랜서 유형과 지역·업종·자본금 등 정형 조건을 기반으로 지원사업 후보를 우선 필터링하고, 사용자의 질문 맥락을 반영해 필요한 정보를 추가로 탐색한다. `[TEAM DECISION]`

- **근거가 보이는 AI 상담:** AI 모드에서는 단순 답변 생성이 아니라 지원사업 원문 또는 데이터에서 확인한 결과를 바탕으로 설명하며, 화면에 참고 자료 출처를 함께 제시한다.

- **계산과 설명의 역할 분리:** 버틸 수 있는 기간, 현금흐름, 대출 원리금, 잔존 채무 등 숫자 계산은 Backend 계산 로직에서 처리하고, 생성형 AI는 계산된 결과와 근거를 사용자에게 이해하기 쉽게 설명하는 역할에 집중한다. `[TEAM DECISION]`

- **진단 → 계산 → 매칭 → AI 설명의 연결:** 기존 서비스가 지원사업 검색 또는 챗봇 상담 중 하나에 집중한다면, 본 서비스는 사용자의 재무 상황을 진단한 뒤 리스크를 계산하고, 그 결과에 맞는 지원사업을 연결한 후 AI가 근거와 함께 설명하는 하나의 흐름으로 구성한다. `[TEAM DECISION]`

## 5. 활용 데이터 및 생성형 AI 모델 적용 방안

### 5-1. 활용 데이터

현재 기획에서 활용 예정인 데이터는 다음과 같다.

- **정부지원금·정책자금 대출·지자체 혜택 데이터**
  - 공공데이터포털 및 지자체 API 등을 통해 수집
  - 지원 대상, 지역, 업종, 신청 조건, 지원 내용, 신청 기간, 출처 등의 정보를 서비스 내 검색·매칭에 활용

- **사용자 프로필 데이터**
  - 사용자 유형: 예비창업자 / 소상공인 / 프리랜서
  - 지역, 업종, 자본금 등
  - 지원사업 후보 필터링과 개인화에 활용

- **사용자 업로드 데이터**
  - 매출장표(CSV/엑셀), 소득 데이터
  - 현금흐름 및 재무상태 진단에 활용

### 5-2. 데이터 처리 구조 `[TEAM DECISION]`

데이터 성격에 따라 한 가지 검색 방식에 모두 의존하지 않고 역할을 분리한다.

1. 공공데이터 및 지원사업 정보를 수집·정규화
2. 지원 대상·지역·업종·기간 등 명확한 조건은 구조화된 데이터베이스에서 필터링
3. 사용자가 입력한 재무 데이터는 Backend에서 계산 가능한 지표로 변환
4. 공고문·지원사업 설명처럼 비정형 문서 해석이 필요한 경우에만 의미 검색을 보조적으로 적용
5. 최종적으로 검증된 검색 결과와 계산 결과를 생성형 AI에 전달
6. 생성형 AI가 사용자 상황에 맞는 설명과 다음 행동을 생성
7. 결과 화면에 지원사업 출처 및 판단 근거를 함께 표시

### 5-3. 생성형 AI의 역할 `[TEAM DECISION]`

생성형 AI는 다음 역할에 집중한다.

- 사용자의 자연어 질문에서 의도·상황·조건 파악
- 복잡한 정부지원사업 문구를 이해하기 쉬운 표현으로 설명
- 여러 지원사업 후보의 차이를 사용자 상황에 맞게 요약
- Backend가 계산한 재무·리스크 결과를 자연어로 해석
- 검색된 근거와 계산 결과를 종합해 AI 상담 답변 생성
- 필요한 정보가 부족한 경우 추가 입력이 필요한 항목을 사용자에게 안내

반대로 다음 항목은 생성형 AI가 임의로 계산하거나 추측하지 않고 Backend 또는 구조화된 검색 로직에서 처리한다.

- 지원 자격의 명시적 조건 필터
- 금액·기간·대출 원리금·잔존 채무 등 수치 계산
- 날짜 및 마감 여부 비교
- 정렬·집계·Top-N
- 데이터에 존재하지 않는 지원사업 또는 제도의 생성

→ `필요 시 비정형 문서 검색`

→ `재무·리스크 계산`

→ `근거 및 계산 결과 검증`

→ `생성형 AI 설명`

→ `출처·추천 근거·다음 행동 표시`

### 5-5. 데이터 관리 원칙 `[TEAM DECISION]`

지원사업 정보는 최신성이 중요하므로 데이터별로 가능한 범위에서 다음 메타데이터를 함께 관리한다.

- `source`
- `source_url`
- `collected_at`
- `effective_date`
- `update_cycle`
- `data_type`

사용자가 업로드한 매출·소득 데이터는 MVP에서 꼭 필요한 범위만 처리하고, 불필요한 개인정보를 장기 저장하지 않는 방향을 우선한다.

## 7. MVP 기술 구조 및 안정성 `[TEAM DECISION]`

### 7-1. MVP 기술 구조

핵심 사용자 흐름을 안정적으로 구현하기 위해 다음과 같이 기능을 분리한다.

`Web Frontend`

→ `Backend API`

→ `프로필·지원조건 처리`

→ `지원사업 Retrieval`

→ `재무·리스크 계산 Engine`

→ `Evidence Validation`

→ `LLM Explanation`

→ `최종 결과 + 출처`

### 7-2. Backend 주요 책임

- 사용자 프로필 입력 검증
- 지원사업 검색 및 조건 필터링
- 매출장표·소득 데이터 입력 처리
- 현금흐름 및 리스크 계산
- AI 상담에 전달할 근거 데이터 구성
- 생성형 AI 호출 및 응답 형식 관리
- 데이터가 없거나 조건을 판단할 수 없는 경우 Unsupported 처리
- Frontend에 결과·출처·계산 근거를 API 형태로 반환

### 7-3. Retrieval 및 계산 원칙

- 숫자·조건·기간·정렬처럼 명확한 값은 **구조화 검색 및 결정론적 계산** 우선
- 지원사업명·기관명 등 정확한 키워드는 **정형 조회 또는 Keyword 검색** 우선
- 공고문 등 비정형 텍스트의 의미 파악이 필요한 경우에만 **Vector Retrieval을 선택적으로 검토**
- 생성형 AI가 데이터에 없는 지원사업, 금액 또는 자격 조건을 임의로 생성하지 않도록 검색 결과를 우선 근거로 사용

### 7-4. 데이터 파이프라인

`공공데이터포털·지자체 API 등 외부 데이터`

→ `수집`

→ `스키마 정규화`

→ `중복·결측·기준일 검증`

→ `서비스 DB 저장`

→ `지원사업 검색/매칭`

→ `출처와 기준일을 포함해 결과 반환`

외부 데이터의 최신성 차이를 고려해 수집 시점과 적용 기준일을 구분해 관리한다.

### 7-5. 배포·인프라

MVP는 심사자가 별도 설치 없이 공개 URL에서 사용할 수 있도록 웹서비스 형태로 배포한다.

배포 단계에서는 다음 항목을 우선 확인한다.

- Public URL 접근
- HTTPS
- Frontend ↔ Backend API 연결
- 환경변수 및 API Key 분리
- 외부 API timeout 및 예외 처리
- 서버 재시작 이후 정상 복구
- DB 연결 상태
- Health Check
- 잘못된 사용자 입력 처리
- LLM 호출 실패 시 전체 서비스가 중단되지 않는 예외 처리
