Last Updated: 2026-08-29

이 문서는 2026 금융 AI Challenge 예선 제출용 웹서비스의
목표 MVP 범위를 관리한다.

주의:

이 문서의 MUST는 현재 개발 목표이다.

최종 기능명세서에는 실제 구현 및 검증 완료된 기능만 작성한다.

구현되지 않은 기능을 제출 문서나 UI에서
구현된 기능처럼 표현하지 않는다.

- 팀명: `start`
- 서비스명: `FinBridge`
- Backend 구축·배포, 디자인, QA 내부 완료 목표: `2026-09-03~04`
- 팀 공유 제출 일정: `2026-09-07 오전` (최종 제출 전 공식 공지 재확인)
- 일정상 새로운 기능을 넓게 추가하기보다 핵심 사용자 시나리오의 완성도와 배포 안정성을 우선한다.


# 1. MVP Goal

심사자가 Public URL에 접속한 뒤

사용자 상황 입력

→ 관련 지원사업 탐색

→ 매칭 근거 확인

→ 재무·창업 리스크 계산

→ AI 설명

→ 출처 및 다음 행동 확인

까지 하나의 사용자 시나리오로 직접 경험할 수 있도록 한다.


# 2. Primary Demo Scenario

MVP의 대표 시나리오는 다음과 같다.

1. 사용자가 FinBridge에 접속한다.
2. 메인 AI모드에서 `일반모드` 또는 `집중모드`를 선택한다.
   - 모드를 선택하지 않고 채팅창에 바로 입력하면 일반모드로 시작한다.
   - 모드 선택 후 첫 채팅 전 예시 질문 2개를 확인할 수 있다.
3. 일반모드는 자연어 질문부터 시작한다.
4. 집중모드는 첫 대화 전에 지원사업 Matching에 필요한 최소 구조화 조건을 체크·선택형 등으로 입력한다.
5. Backend가 실제 확보된 지원사업 데이터에서 관련 후보를 검색한다.
6. 구조화 가능한 자격조건은 Backend가 deterministic matching으로 비교한다.
7. AI는 조건 충족·추가 확인·판단 불가 등의 구조화된 결과를 GPT/Claude와 유사한 대화형 문장으로 설명한다.
8. 사용자는 지원사업 리스트에서 공고 이미지 + 기존 텍스트 정보를 보고 상세 화면으로 이동한다.
9. 상세 화면에서 공식 출처를 확인하거나 해당 `program_id`를 들고 AI모드로 이동해 이어서 질문할 수 있다.
10. 사용자는 리스크 계산기, 소득 안정성 등 자신의 유형에 맞는 분석 기능을 확인한다.
11. 소상공인 매출장표 분석은 Public URL에서 진입 가능해야 하며, 실제 분석이 일정 내 완성되지 않으면 실제 분석으로 오인되지 않는 `DEMO SAMPLE` 상태를 제공한다.
12. 사용자는 공식 출처, 판단 근거, 리스크 결과 및 다음 행동을 확인한다.

# 3. MUST — 제출 MVP 핵심 기능

아래 기능은 제출 MVP에서 우선적으로 완성한다.


## M1. 사용자 유형 선택

사용자는 다음 세 유형 중 하나를 선택할 수 있다.

- 예비창업자
- 소상공인
- 프리랜서

Status:
PLANNED


## M2. 사용자 프로필 입력

지원사업 탐색에 필요한 최소 프로필을 입력한다.

현재 후보:

- 사용자 유형
- 지역
- 업종
- 자본금

실제 필드는 확보한 지원사업 데이터 Schema에 맞춰 확정한다.

Status:
PLANNED


## M3. 지원사업 데이터 조회

실제로 확보하고 검증한 공개 데이터를 Backend에서 조회한다.

대상 후보:

- 정부지원사업
- 정책자금
- 지자체 지원사업

지원사업 데이터가 확보되지 않은 상태에서
가상의 지원사업을 생성하지 않는다.

Status:
PLANNED


## M4. 사용자 조건 기반 지원사업 Matching

사용자 프로필과 지원사업의 명시적 조건을 비교한다.

명확한 조건은 LLM이 아닌
structured query 또는 deterministic logic으로 처리한다.

예:

- 지역
- 대상 유형
- 업종
- 신청 기간
- 기타 실제 Dataset에서 확인 가능한 조건

Status:
PLANNED


## M5. Match Evidence 표시

지원사업 결과에 단순 추천 점수만 표시하지 않는다.

가능한 범위에서 다음을 표시한다.

- 일치한 조건
- 추가 확인이 필요한 조건
- 정보 출처
- 기준일 또는 수집일

지원 자격을 확인할 수 없는 경우
임의로 적격 판정을 내리지 않는다.

Status:
PLANNED


## M6. 지원사업 상세 조회

사용자가 추천 또는 검색된 지원사업을 선택하면
주요 내용을 확인할 수 있다.

예:

- 사업명
- 운영기관
- 주요 지원 내용
- 주요 대상
- 신청 기간
- 출처

실제 데이터에 존재하는 항목만 표시한다.

Status:
PLANNED


## M7. 재무·창업 리스크 계산

사용자가 입력한 값을 기반으로
Backend에서 deterministic calculation을 수행한다.

현재 기획상 후보 입력:

- 초기 비용
- 매출
- 지출
- 대출 조건

현재 기획상 후보 출력:

- 자금 소진 속도
- 버틸 수 있는 기간
- 사업 악화 시 재무 상태
- 폐업 가정 시 잔존 채무

최종 계산식과 입력값은 별도 검증 후 확정한다.

LLM에게 계산을 수행시키지 않는다.

Status:
PLANNED


## M8. AI 결과 설명

생성형 AI는 Backend가 생성한

- 사용자 조건
- 지원사업 검색 결과
- Matching Evidence
- 계산 결과

를 받아 사용자에게 설명한다.

AI는 존재하지 않는 지원사업이나
금융수치를 새로 생성해서는 안 된다.

Status:
PLANNED


## M9. 출처 표시

최종 결과에서 사용자가
정보의 원출처를 확인할 수 있어야 한다.

가능하면 다음을 제공한다.

- source
- source_url
- 기준일 또는 수집일

Status:
PLANNED


## M10. Unsupported / 추가확인 처리

데이터만으로 판단하기 어려운 경우
AI가 임의로 결론을 내리지 않는다.

예:

- 추가 확인 필요
- 데이터 없음
- 현재 정보만으로 판단 불가

등의 상태를 제공한다.

Status:
PLANNED


## M11. Public Web Service

심사자가 별도 설치 없이
제출 URL에서 주요 기능을 직접 사용할 수 있어야 한다.

최소 조건:

- Public URL
- Frontend 접근 가능
- Backend 정상 연결
- 핵심 API 정상 작동
- 오류 입력 처리
- 서비스 재시작 후 정상 동작

Status:
PLANNED



## M12. 일반모드 / 집중모드 및 연속 대화

AI모드에서 다음 UX를 제공한다.

### 일반모드

- 자연어 중심의 편한 대화
- 모드 미선택 상태에서 바로 입력하면 자동 일반모드
- 필요 시 집중모드 전환 제안

### 집중모드

- 첫 대화 전 최소 구조화 조건 입력
- 첫 입력 이후 자연어 기반 대화 지속
- 매 턴 폼 입력을 강제하지 않음

두 모드 모두 첫 대화 전 예시 질문 2개를 제공한다.

Status:
PLANNED


## M13. 매출장표 분석 진입점 / 데모 Fallback

소상공인용 매출장표 분석은 제출 Public URL에서 기능 진입점과 결과 화면이 존재해야 한다.

우선순위:

1. 실제 CSV/Excel 업로드 및 Backend 분석 구현
2. 일정 부족 시 `DEMO SAMPLE`임을 명확히 표시한 샘플 결과 화면

금지:

- 샘플 결과를 실제 업로드 분석으로 표시
- 하드코딩 값을 실제 AI 또는 실제 금융 분석 결과로 설명

실제 분석 기능이 검증되지 않았다면 공식 기능명세서에 구현 완료 기능으로 기재하지 않는다.

Status:
PLANNED


## M14. 프리랜서 소득 안정성 간이 분석

기간별 소득 입력을 기반으로 MVP에서 설명 가능한 범위의 간이 안정성 지표를 제공한다.

원칙:

- deterministic calculation 우선
- 금융기관 수준의 신용평가 또는 대출 승인 판단으로 표현하지 않음
- 결과 영역에 작은 회색 주의사항 표시
- 최종 계산식과 입력값은 구현·테스트 후 Freeze

Status:
PLANNED

# 4. SHOULD — 시간 허용 시 구현

MUST 기능이 안정적으로 작동한 이후에만 구현한다.


## S1. CSV / Excel 매출장표 실제 업로드·분석

매출장표 기능의 **화면 진입점은 MUST**이지만, 임의의 모든 회계 파일을 처리하는 실제 업로드·분석 범위는 SHOULD로 둔다.

실제 구현 시:

- 팀이 정의한 Sample Schema 우선
- 지원 형식/필수 컬럼/단위 검증
- 잘못된 파일 오류 처리
- 원본 금융 데이터 장기 저장 최소화

일정 내 실제 분석이 완성되지 않으면 M13의 명확히 라벨링된 Demo Fallback을 사용한다.

Status:
OPTIONAL

## S2. 프리랜서 소득 안정성 상세 분석 고도화

M14의 간이 분석을 넘어 다음과 같은 상세 기능은 시간 허용 시에만 구현한다.

- 더 긴 기간의 소득 패턴 분석
- 복수 안정성 지표
- 고급 시각화
- 추가 금융 해석

Status:
OPTIONAL

## S3. 사용자 유형별 고급 Widget 구성

M7·M13·M14의 핵심 기능 존재 여부와 별개로, 마이페이지에서 사용자 유형에 따라 고급 시각화·추가 Widget을 더 세분화하는 것은 시간 허용 시에만 적용한다.

예:

- 예비창업자: 리스크 상세 시각화
- 소상공인: 매출 추가 지표
- 프리랜서: 소득 안정성 상세 시각화

Frontend 일정과 Backend 기능 완성도를 확인한 후 적용한다.

Status:
OPTIONAL


## S4. 지원사업 비교

두 개 이상의 지원사업을 선택해
주요 조건을 비교하는 기능.

Status:
OPTIONAL


## S5. 고급 대화 메모리 / 복잡한 멀티세션 기능

같은 세션에서 일반적인 후속 대화를 이어가는 기능은 M12 범위에 포함한다.

다음은 이번 MVP에서 필수가 아니다.

- 장기 사용자 메모리
- 여러 세션 간 복잡한 대화 상태 복원
- Multi-Agent 기반 장기 Workflow

Status:
OPTIONAL

# 5. NOT MVP — 이번 예선에서 우선 제외

다음 기능은 핵심 MVP가 완성되기 전에는 개발하지 않는다.


## N1. 실제 지원사업 신청 대행

이번 MVP에서 실제 신청 제출까지 자동화하지 않는다.


## N2. 지원서 자동 제출

정부 또는 지자체 시스템에
사용자 대신 자동 제출하지 않는다.


## N3. 실제 대출 신청

금융기관에 실제 대출 신청을 수행하지 않는다.


## N4. 대출 승인 예측 보장

사용자의 실제 대출 승인 여부를
AI가 확정적으로 예측하거나 보장하지 않는다.


## N5. 실제 신용평가 모델

금융기관 수준의 신용평가 모델을
이번 MVP 핵심 범위로 두지 않는다.


## N6. 마이데이터 직접 연동

실제 금융기관 계좌 또는
마이데이터 API 직접 연동은 우선 제외한다.


## N7. 세무사·컨설턴트 Marketplace

장기 확장 기능으로 관리한다.


## N8. B2B SaaS 기능

지자체·창업지원기관용 관리자 SaaS는
확장 방향으로만 유지한다.


## N9. 복잡한 Multi-Agent System

핵심 기능 구현에 필요성이 검증되지 않는 한 제외한다.


## N10. Graph DB

명확한 성능 또는 사용자 가치 개선이 검증되지 않는 한 제외한다.


## N11. Vector DB 전면 적용

비정형 공고문 검색에서 실제 필요성이 확인될 경우에만
일부 적용을 검토한다.


# 6. MVP Success Criteria

MVP는 단순히 화면이 존재한다고 완료로 판단하지 않는다.

다음 시나리오가 실제로 작동해야 한다.


## Scenario A — 지원사업 탐색

사용자 프로필 입력

→ Backend 요청

→ 실제 지원사업 데이터 검색

→ 사용자 조건 Matching

→ 결과 반환

→ Matching Evidence 확인

→ 원출처 확인


## Scenario B — 리스크 계산

재무 입력

→ Backend Calculation

→ 계산 결과 반환

→ 사용자 화면 표시


## Scenario C — AI 설명

검색 결과 + 계산 결과

→ LLM 입력

→ 근거 기반 설명

→ 사용자 화면 표시



## Scenario D — AI 모드 전환

메인 진입
→ 일반모드 / 집중모드 선택 또는 바로 입력
→ 일반모드 자동 진입 또는 집중모드 구조화 입력
→ 후속 자연어 대화
→ 필요 시 일반모드에서 집중모드 제안


## Scenario E — 지원사업 상세 ↔ AI 채팅

지원사업 리스트
→ 공고 이미지 + 텍스트 카드 확인
→ 상세 조회
→ 공식 출처 확인
→ `AI에게 이 공고 물어보기`
→ `program_id` context를 포함한 채팅 이동


## Scenario F — 유형별 분석 도구

마이페이지 또는 관련 진입점
→ 리스크 계산 / 매출장표 분석 / 소득 안정성
→ 실제 구현 기능은 계산·분석 결과 표시
→ 미완성 매출장표 기능은 `DEMO SAMPLE`임을 명확히 표시

# 7. Minimum Demo Quality

심사 시 다음 상태는 피한다.

- 빈 화면
- 핵심 지원사업 Matching·리스크 계산·AI 설명이 Mock UI만 존재
- 버튼이 작동하지 않음
- 검색 결과 하드코딩
- 존재하지 않는 지원사업 출력
- 계산 결과를 실제 계산인 것처럼 하드코딩
- `DEMO SAMPLE` 표시 없이 샘플 매출장표 결과를 실제 분석처럼 표현
- 출처 링크 없음
- LLM이 계산값을 임의 생성
- Backend와 Frontend 내용 불일치
- 특정 개발자 PC가 켜져 있어야 작동


# 8. Scope Reduction Rule

2026-09-03~04 내부 완료 목표를 넘기지 않기 위해 범위를 다음 순서로 줄인다.

먼저 제거 또는 축소:
